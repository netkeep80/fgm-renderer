# Первый кадр FGM

Обе сборки читают одну синтетическую сферу и выбирают её поле на плоскости через принятое ядро C05. Общий шейдер WGSL раскрашивает значения поля на сетке 128×128. Браузер показывает буфер на холсте, нативная программа сохраняет кадр PPM. Оба варианта выполняют шейдер через WebGPU. Сцена демонстрирует перенос вычислительного пути. Пространственная видимость и рекурсивная композиция входят в V02. [V01-BOOT](https://github.com/netkeep80/fgm-renderer/issues/5) · [V02](https://github.com/netkeep80/fgm-renderer/issues/6)

## Браузер

Активируйте Emscripten 4.0.21, установите CMake 3.24 или новее и Node.js 22 или новее. Выполните команды из корня репозитория.

~~~sh
npm ci
emcmake cmake -S . -B build/wasm -DCMAKE_BUILD_TYPE=Release
cmake --build build/wasm --parallel
npm run build
python -m http.server 8000 --bind 127.0.0.1 --directory build/web
~~~

Откройте http://127.0.0.1:8000 в браузере с поддержкой WebGPU. Кнопка перезапуска уничтожает устройство. Обработчик потери заново создаёт устройство и повторяет вывод. Повторная непреднамеренная потеря при автоматическом восстановлении завершает попытку с сообщением. Если API или адаптер недоступны, страница сообщает причину.

Готовый браузерный пакет и кадры сохраняются в артефакте `fgm-boot` успешного прогона CI. Для пакета достаточно распаковать артефакт и открыть каталог с `index.html` через локальный HTTP-сервер. Сборку WASM на своём компьютере в этом случае можно пропустить.

## Нативный кадр

Распакуйте подходящий архив wgpu-native v29.0.1.1. Нужны CMake и компилятор C++20. Под Linux требуется доступный Vulkan-адаптер, например Mesa lavapipe. Для Windows предусмотрен архив MSVC x86-64 и копирование DLL рядом с исполняемым файлом. [Архивы wgpu-native](https://github.com/gfx-rs/wgpu-native/releases/tag/v29.0.1.1)

~~~sh
cmake -S . -B build/native -DCMAKE_BUILD_TYPE=Release -DWGPU_ROOT=/path/to/wgpu
cmake --build build/native --config Release --parallel
build/native/fgm_boot web/sphere.fgm.json web/scene.wgsl build/native/sphere.ppm
~~~

При сборке Visual Studio исполняемый файл находится в `build/native/Release/fgm_boot.exe`. Сборка получает `fgm-core` на принятом коммите `ba91a5e96d9f4f9580c9b2e9a9460b97acb7f01b`. Для локального исходного дерева доступно стандартное переопределение `FETCHCONTENT_SOURCE_DIR_FGM_CORE`.

## Проверка

`npm run test:browser` запускает подготовленный пакет в Chromium и сравнивает каждый RGB-канал с кадром PPM. Тест проверяет фон, наличие фигуры, непрозрачность кадра и повторный кадр после перезапуска устройства. Отдельно проверяется сообщение об отсутствии WebGPU. Для другого пути к нативному кадру используется `FGM_NATIVE_FRAME`, для установленного Chromium — `FGM_CHROMIUM`. Программный адаптер CI подтверждает один воспроизводимый путь исполнения.
